# Phase 6 plan: Cluster and Eval plugins

[ADR 12](../adr/12-cluster-and-eval-plugins.md). Two built-in plugins shipped in
the library, **neither in `:defaults`**: a host adds them to `plugins:`.

## Task 1: Cluster plugin

- `PhoenixDevToolbar.ClusterInfo.read(timeout)`: this node (name, distributed or
  not) and up to 50 connected nodes (`Node.list(:connected)`, visible or hidden),
  each read in its own task with a deadline: round trip time of a first `:erpc`
  call, process count, total memory, OTP release, uptime. Only stdlib functions are
  called remotely (the other node may not have this library). A node that does not
  answer in time shows as such.
- `Plugins.Cluster` (`:cluster`, "Cluster"), option `refresh_ms:` (5000, 1000 to
  60000). The tab reads in `start_async/3` while shown and visible, every
  `refresh_ms`; never in the panel process.
- Tests: the not distributed state, the local node's row, the option bounds.
  A real second node needs distribution in the test VM: left out (ADR open limit).

## Task 2: Eval plugin (risky: code execution, combined review)

- `Plugins.Eval` (`:eval`, "Eval"), options validated in `init/1`, each override
  warned at attach:
  - `allow:` `:read_only` (default) or `:eval`.
  - `clients:` `:loopback` (default) or `:any`: the panel's websocket peer
    (`pdt_actions.client`, given to built-in tabs only) must be a loopback
    address unless `:any`.
  - `timeout_ms:` (5000, 100 to 60000).
- Read only: a fixed list of read queries (memory, system and build info, run
  queue, started applications, ETS tables by memory, port and process counts,
  registered names), picked by id from a select, never by code.
- Eval (only with `allow: :eval`): a textarea (at most 10 000 bytes), run in a
  task with its own group leader (`StringIO`, so `IO.puts` output is captured)
  that is killed after `timeout_ms`; the result inspected and truncated, an
  exception formatted, the output truncated. Each run is logged with
  `Logger.info/1` (its size, never its code). The last 10 runs are kept.
- Tests: read only by default (no editor, a forged `eval` event refused), a
  query, eval of an expression with output, a raise, a timeout, a client off this
  machine refused, `clients: :any` allowed, option validation and warnings.

## Risks

- **Remote code execution**: Eval is opt-in, read only and loopback only by
  default; `allow: :eval` plus `clients: :any` is RCE for whoever reaches the dev
  server, warned at attach and documented. The panel socket's own checks still
  apply (signed session, `check_origin`).
- **Host blocking**: eval runs in a task killed on timeout; cluster calls have a
  deadline per node; neither runs in the panel process.
- **Memory**: 10 runs kept, results and output truncated; 50 nodes.
- **Atoms**: evaluated code can create atoms: the developer typed it (noted).
- **Prod**: plugins are only attached when enabled; nothing new in the host.
