# Roadmap

Phases of `phoenix_dev_toolbar`. Each phase gets its own dated plan
(`docs/YYYY-MM-DD-phaseN-plan.md`, with a "Risks" section) when it starts, then
ADR updates, CHANGELOG lines, `mix precommit` and a manual check in `mix dev`.
Tick a phase here when it lands.

## Phase 0: Way of working and spike

- [x] Conventions: AGENTS.md, ADRs 00 to 06, CHANGELOG, `mix precommit`, CI
- [x] Spike against LiveView 1.1 source (`deps/phoenix_live_view`), results into ADR 02:
  - exact telemetry event names and metadata (`live_view` and `live_component`, incl. `update`)
  - `socket.assigns.__changed__` availability in `:stop` metadata
  - `Phoenix.LiveView.Debug` API (list LiveViews, socket, live components)
  - `liveSocket.socket.ping/1` in `phoenix.js`, `[data-phx-main]` id vs `socket.id`

## Phase 1: MVP (core engine, overlay, Ecto)

- [x] `Application` supervision tree guarded by `enabled?/0`: `Store`, `Registry`, `Collector`
- [x] `Store`: ETS tables, caps, TTL sweep, flood guard, DOWN cleanup (ADR 03)
- [x] `Collector`: attach/detach, attribution (`pdict`, `$callers`), crash-safe handlers (ADR 02)
- [x] `Truncate` + redaction helpers
- [x] `Plug`: sid, HTML injection rules, asset serving (ADR 04)
- [x] `PanelLive` + panel layout, served by the plug (no router macro, ADR 01)
- [x] `loader.js` (iframe, collapse, postMessage bridge), esbuild into `priv/static`
- [x] Request panel (route, controller/LiveView, status, timings)
- [x] Ecto panel (SQL, params, total/queue/query/decode, source, stacktrace origin)
- [x] `dev.exs` harness with `ecto_sqlite3`, `mix dev`
- [x] CI prod-compile fixture host app (ADR 01)

## Phase 2: LiveView insights

- [x] Lifecycle profiler: mount, handle_params, handle_event, render, component update timings
- [x] Assigns inspector: snapshot + per-event diff of changed keys, truncated, redacted
- [x] Event log: server callbacks + client `phx:*` events from the loader
- [x] Component tree via `Phoenix.LiveView.Debug`, follows live navigation

## Phase 3: Plugin system

- [x] Public `PhoenixDevToolbar.Plugin` behaviour + `use` macro (ADR 05)
- [x] Built-ins refactored onto the behaviour, `:defaults` expansion, config validation
- [x] Plugin quarantine on crash, error surfaced in the panel
- [x] Per plugin event caps, so LiveView events no longer push out queries (ADR 03)
- [x] Plugin guide in ExDoc + example plugin in `examples/` (for example Oban)
- [ ] Optional Igniter installer (deferred to its own phase)

## Phase 4: Advanced diagnostics

- [x] N+1 detector: same SQL + origin repeated >= 5 times in one callback span, configurable (ADR 08)
- [x] `EXPLAIN` action on captured SELECTs, rolled back, never ANALYZE (ADR 08)
- [ ] Socket RTT sampling and sparkline
- [x] Process panel: memory, message queue, GC, reductions, links, monitors, `$callers` children, GC now (ADR 09)
- [ ] Opt-in `handle_info` tracing via `:erlang.trace/3`, rate limited

## Release

- [x] Public repository readiness: Credo defaults, limits validation, panel headers, SECURITY.md
- [ ] First Hex release: bump `@version`, tag `v<version>` (ExDoc's `source_ref`), `mix hex.publish`
