# Phase 1 plan: MVP (core engine, overlay, Request and Ecto panels)

Goal: install the library in a Phoenix 1.8 app, open any page, see a collapsed
toolbar with request timing and query count, expand it to list the queries of
that page (dead render + connected LiveView + its `Task` children), live.

Decisions live in ADR 01 to 04 and 06; this file is the build order.
Plugins stay internal in this phase (ADR 05 lands in Phase 3), but built-ins are
already shaped as plugin modules so the refactor is mechanical.

## Tasks

Each task is one subagent sized slice (under ~40 turns), tests first.

1. **Truncate and redaction** (`lib/phoenix_dev_toolbar/truncate.ex`)
   - `inspect_value/2` (limit 50, printable_limit 1024), `sql/1` (8 KB), `stacktrace/1`
     (10 frames, drop our own and `:telemetry` frames), `redact/2` on maps and keyword lists
   - Pure functions, doctests
2. **Event and Session structs** (`event.ex`, `session.ex`)
   - `%Event{sid, seq, plugin, kind, at, duration, data}`, `%Session{sid, parent, kind
     (:request | :live_view), owner, transport, view, path, started_at, count, dropped}`
3. **Store** (`store.ex`, risky: combined review)
   - ETS tables `:pdt_events`, `:pdt_sessions`, `:pdt_pids`, `:pdt_socket_ids`; `:atomics` seq + flood counters
   - API: `new_session/1`, `link_socket_id/2`, `sid_for_socket_id/1`, `track_pid/2`,
     `sid_for_pid/1`, `insert/2`, `events/2` (since seq), `session/1`, `latest_for_transport/1`
   - Caps, TTL sweep, DOWN monitor with 60 s grace, flood guard, trimming via deduplicated cast
   - Tests: caps and eviction order, TTL with injected clock, DOWN cleanup with
     `Process.monitor` + `:sys.get_state/1` (no sleeps), flood counter reset
4. **Registry and notify** (`notify.ex`)
   - `PhoenixDevToolbar.Registry` (duplicate keys); `subscribe/1` (sid or `{:transport, pid}`),
     `notify/1` dispatches `{:pdt_event, sid}` without payload
5. **Collector and attribution** (`collector.ex`, `attribution.ex`, `live_view_compat.ex`, risky)
   - `attach/0` / `detach/0` with ids `{PhoenixDevToolbar, group}`; every handler body in `try/rescue`, log once per handler via `:persistent_term` flag
   - `Attribution.current_sid/0`: pdict, then `$callers` through `Store.sid_for_pid/1`
   - LiveView mount `:start` handler: request process indexes `socket.id -> sid`;
     LiveView process resolves sid by `socket.id`, else new sid with `parent` =
     `Store.latest_for_transport(socket.transport_pid)`, else inherits from `socket.root_pid`
   - Ignore `PhoenixDevToolbar.PanelLive` and requests under the toolbar path
   - Tests: synthetic `:telemetry.execute/3` in tracked, untracked and `Task.async` processes;
     a raising plugin does not detach the handler
6. **Built-in collectors** (`plugins/request.ex`, `plugins/ecto.ex`)
   - Request: `router_dispatch` start/stop/exception (route, plug, plug_opts, status)
   - Ecto: per configured repo, read `telemetry_prefix` from `repo.config()` (default from module
     name); record SQL, cast params (redacted), source, the four timings in microseconds,
     stacktrace origin when present. Skip when `ecto_sql` is not loaded
7. **Plug** (`plug.ex`, risky)
   - `init(path: "/__pdt")`; no-op when not enabled or path under the toolbar prefix
   - Serves `<path>/assets/*` from `priv/static` with cache headers
   - New request sid in pdict + `conn.private[:phoenix_dev_toolbar]`, `before_send` records
     duration + status and injects the loader on `text/html` 200, not chunked, with
     `</body>`; nonce from `conn.assigns[:csp_nonce]` (key configurable)
   - Tests with `Plug.Test`: each injection rule, nonce, asset serving, skip own paths
8. **Router macro and PanelLive** (`router.ex`, `panel_live.ex`, `components/*.ex`)
   - `dev_toolbar(path, opts)` expands to a `live_session :phoenix_dev_toolbar` with our
     root layout and `live "/panel", PanelLive`; empty expansion when not enabled at compile time
   - `PanelLive`: `?sid=` param, subscribes to sid and its transport, reads events since last
     seq, throttles re-render (100 ms timer), tabs Request / Ecto, badge summary
   - Own root layout loading `panel.js` and `panel.css` from `<path>/assets`
   - `LiveViewTest`: render with seeded Store, live update on notify, follows live navigation
9. **Assets** (`assets/loader.js`, `assets/panel.js`, `assets/panel.css`)
   - `esbuild` hex package `only: :dev`, `mix assets.build` alias writes to `priv/static`
     (committed); `panel.js` bundles `phoenix` and `phoenix_live_view` JS from `deps/`
   - Loader: iframe container, collapse state in `localStorage`, `postMessage` bridge stub
     (RTT and `phx:*` forwarding filled in Phase 2 and 4)
   - Hand written CSS, no Tailwind (keeps the package free of a CSS toolchain)
10. **Dev harness** (`dev.exs`, `mix dev`)
    - Endpoint + router + 3 LiveViews (list with N queries, form with events, `Task.async`
      queries) + `ecto_sqlite3` repo with an in-memory or `tmp/dev.db` database, migrated at boot
    - Add `dev.exs` to `.credo.exs` included files
11. **Prod fixture and docs**
    - `test/fixtures/host_app` minimal app compiled in CI with `MIX_ENV=prod` without the dep
    - README installation section, `@moduledoc` for public modules, ADR 01 to 04 and 06
      flipped to `Implemented (date)` where shipped, CHANGELOG lines

Order: 1, 2 → 3 → 4 → 5 → 6 and 7 in parallel → 8 → 9 → 10 → 11.

## Risks

- **Hot path**: untracked handler path is one `Process.get/1`; benchmarked once in `bench/`
  before closing the phase. No `GenServer.call` from handlers (Store writes are direct ETS)
- **Prod footprint**: router macro and plug are no-ops when disabled; fixture app proves the
  guarded install compiles in prod
- **Memory**: Store caps tested; payload truncation applied in collectors, not in the panel
- **Host conflicts**: own paths never get the loader injected (else the iframe loads a toolbar
  inside itself); panel LiveView and its queries are never tracked; nonce support for CSP;
  `before_send` must not break `send_file` or chunked responses
- **Panel uses the host's `/live` socket and `:browser` pipeline**: host auth plugs in that
  pipeline may redirect the iframe; documented, `pipe_through` is the host's choice
- **Public API**: `PhoenixDevToolbar.Plug` (it also serves the panel; the router macro was dropped, ADR 01), config keys documented
  in ExDoc; everything else `@moduledoc false`
- **Tests and ADR sync**: ADR 02 to 04 updated in place for any deviation found while building
